# Experience Input｜经历来源与事实母库验收

本阶段只解决一个问题：**是否已经有足够真实的个人经历事实，可以安全进入简历生成。**

## 1. 接受的输入

优先级从高到低：
- 已整理的《个人经历.md》事实母库
- 旧简历 + 项目材料 / 实习记录
- 作品说明 / PRD / 复盘 / 项目文档
- 用户自述

多份材料可以合并，但冲突处必须保留冲突，不得擅自选一个版本当真相。

## 2. 没有经历文件时

不要边问几句边直接写简历。

读取 `../assets/experience-miner-prompt.md`，将其中完整 Prompt 原样提供给用户，让用户在 GPT 中完成苏格拉底式经历深挖并返回《个人经历.md》。此时流程暂停在 Gate B。

如果用户明确要求就在当前 Codex 对话里完成经历深挖，也可以按该 Prompt 执行，但仍必须完成事实母库后再进入简历阶段。

## 3. 经历文件最低验收

对准备进入简历的每段重点经历，至少能回答：

```text
经历是什么 / 时间
业务或用户场景
原始问题或目标
本人负责什么
本人不负责什么
关键动作
至少一个关键判断或取舍
协作对象
产出物
结果
结果证据或数字来源
未完成 / 失败 / 局限
本人 / 团队 / AI 贡献边界
```

不是每段都必须有漂亮业务结果，但必须知道“最后发生了什么”。

## 4. 事实可信度标签

内部给关键事实标记：

- `A 强事实`：正式上线/真实使用/系统数据/财务数据/负责人验收/明确奖项等
- `B 边界事实`：历史对照、小样本、人工统计、内部测试、定性反馈、合理估算
- `C 背景事实`：动机、探索、失败、转折、兴趣来源
- `U 未确认`：记忆模糊、来源不明、材料冲突

`U` 不得直接写成简历强结论。

## 5. 数字核验

任何亮眼数字至少确认：
- 数字是什么口径
- 来源是什么
- 时间范围
- 是本人结果还是团队结果
- 是否估算

用户只记得“大概一半”时，写“约 50%”并保留估算边界，不制造 47.3% 这种看着很科学、实际上只是小数点 cosplay 的数字。

## 6. AI / 工具贡献边界

如果使用 ChatGPT、Codex、Claude、Gemini、Cursor、Copilot、Agent、自动化工具等，分开记录：

### 用户贡献
目标定义、约束、判断、取舍、验收、迭代要求、业务决策。

### AI / 工具贡献
代码生成、方案建议、文案生成、初版搭建、批处理、设计生成等。

禁止把“AI 生成的架构”直接写成“本人设计架构”；也不要把真实的目标定义和验收工作抹掉。

## 7. Gate B

只有当目标岗位最可能使用的 2–5 段经历具备基本事实闭环时通过。

若经历存在缺口：
- 缺的是高价值事实 → 只追问一个最影响简历可信度的问题；
- 缺的是低价值细节 → 标记未知，不阻塞；
- 核心能力完全没有证据 → 不编，留到能力缺口里。
