# Experience Input｜经历来源与事实母库验收

本阶段只解决：**是否已有足够真实的个人经历事实，可以安全进入简历生成。** 两条经历路径最终都收敛到工作区 `03_个人经历.md`。

进入本阶段前读取 `02_<行业><岗位>核心能力.md`，用它识别需要证明的能力，不反过来为了能力模型编经历。

## 1. Phase 2 入口分流（强制顺序）

Phase 2 不能默认进入 Codex 深挖。必须先判断当前任务里是否已经有可用经历材料。

只允许把以下内容视为“已有材料”：
- 用户在当前会话已经上传的简历 / 项目材料 / PRD / 复盘 / 作品说明；
- 用户已经明确提供的文件路径；
- 当前 JobHuntBot workspace 中已经存在且有真实内容的 `03_个人经历.md` 或其他用户经历材料。

**不得为了判断有没有材料而主动扫描** Downloads / Desktop / Documents / Home / 其他项目目录。

分流：

```text
当前任务是否已经有可用经历材料？
├─ YES：读取并核验 → 找能力证据缺口 → 只补问必要问题
└─ NO ：当前轮只给用户两个选择，然后停止
        1. GPT 一问一答（复制 Prompt，带回结果）
        2. Codex 当前会话一问一答
```

### 1.1 已有资料

已有资料时直接读取核验，多份材料冲突时保留冲突，不擅自选一个版本当真相。若材料已足够支撑目标岗位能力，不强制重跑完整挖掘，也**不再要求用户选择 GPT / Codex**。

### 1.2 当前没有可用资料

这一轮用户可见回复必须只完成“路径选择”，不要同时开始经历挖掘，也不要附加工作经历问题。

推荐固定表达：

> 接下来进入经历挖掘阶段，你可以选一种方式：
>
> 1. **在 GPT 里完成**：我把完整经历挖掘 Prompt 给你，你在 GPT 里一问一答完成，最后把《个人经历.md》带回来。
> 2. **直接在 Codex 里完成**：我就在当前会话一次问你一个问题，逐步挖掘经历，最后生成《个人经历.md》。
>
> 回复 1 或 2 即可。

这一轮到此结束。

禁止行为：
- 用户还没选路径就直接问“你之前有过工作经历吗？实习也算。”；
- 把“工作经历首问”和“如果你有旧简历也可以给我”混在同一轮；
- 因为用户没有主动上传材料，就擅自默认他选择 Codex；
- 因为 Agent 更方便，就默认把用户赶去 GPT。

如果用户没有回复 1/2，而是直接上传材料或给出明确路径，则转入“已有资料”分支，不需要再逼他选路径。

## 2. 路径一：GPT

用户明确回复 `1` / 选择 GPT 后：

1. 读取 `../assets/experience-miner-prompt.md`；
2. 把完整、最新的经历挖掘 Prompt 交给用户；
3. 告诉用户：复制到 GPT → 一问一答完成 → 最终输出《个人经历.md》→ 带回 JobHuntBot；
4. 当前 Phase 2 暂停在 Gate B。

没有拿到结果前，不进入正式简历生成。

## 3. 路径二：Codex

**只有用户明确回复 `2` / 选择 Codex 后**才进入本节。

第一问固定：**“你之前有过工作经历吗？实习也算。”**

有工作/实习 → 优先深挖工作、实习、兼职，再补校园/项目；没有 → 直接进入课程项目、比赛、社团、个人项目、创业尝试、研究、作品、志愿等，不继续逼问工作经历。

### 一问一答

一次只问一个高信息增益问题，根据上一答决定下一问。内部可用骨架：

`Context / Trigger / Goal / Constraint / Problem / Decision / Action / Collaboration / Artifact / Evidence / Outcome / Failure / Reflection / Transition`

不要把字段一次性甩给用户。

## 4. 重点经历最低事实闭环

准备进入简历的每段重点经历至少能回答：
- 经历与时间；业务/用户场景；原始问题/目标；
- 本人负责什么、明确不负责什么；
- 关键动作与至少一个判断/取舍；
- 协作对象与产出物；
- 最终结果；结果证据/数字来源；
- 未完成/失败/局限；
- 本人 / 团队 / AI 贡献边界。

不是每段都必须有漂亮商业数字，但必须知道最后发生了什么。

## 5. 事实可信度

- `A 强事实`：上线/真实使用/系统或财务数据/负责人验收/明确奖项等；
- `B 边界事实`：历史对照、小样本、人工统计、内部测试、定性反馈、合理估算；
- `C 背景事实`：动机、探索、失败、转折、兴趣来源；
- `U 未确认`：记忆模糊、来源不明、材料冲突。

`U` 不得写成简历强结论。

## 6. 数字与权责核验

亮眼数字至少确认：口径、来源、时间范围、本人还是团队、是否估算。用户只记得“大概一半”就写“约 50%”，不要制造小数点 cosplay。

使用 AI/Codex/Claude/Gemini/Cursor 等时区分：用户负责目标、约束、判断、取舍、验收、业务决策；AI/工具负责代码/初版/建议/批处理等真实部分。AI 生成 ≠ 用户本人设计。

禁止为了 STAR 完整性补：数字、结果、用户量、上线、测试、团队规模、AI 深度、协作对象。

## 7. 输出 `03_个人经历.md`

统一写入当前 workspace。它是事实母库，不是简历，默认第一人称，包含：时间线、真实场景、目标、本人角色、关键判断、行动、协作、产出、结果、证据、失败/局限、AI/团队边界、当前复盘。

覆盖目标岗位最可能使用的 2–5 段重点经历即可，不考古低价值细节。

## 8. Gate B

目标岗位最可能使用的重点经历具备基本事实闭环才通过。高价值事实缺失时一次只追问一个关键问题；低价值细节可以标未知；核心能力完全没有证据时保留为缺口，不编。
