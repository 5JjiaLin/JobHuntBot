# Experience Input｜通用事实骨架 × 岗位能力定向深挖

本阶段的目标不是“把用户问一遍人生”，而是建立一份**长期可复用的真实经历事实母库**，并根据当前目标岗位的核心能力决定哪些地方值得继续深挖。

核心原则：

> **通用事实骨架负责保真和复用；岗位能力只决定追问优先级与深度，不决定答案应该是什么。**

所有路径最终收敛到当前工作区的 `03_个人经历.md`。

进入 Phase 2 前必须读取 `02_<行业><岗位>核心能力.md`。它用于寻找证据和缺口，不允许反过来诱导用户“补出”岗位想要的经历。

---

## 1. 先判断经历材料成熟度，不要一刀切重挖

只允许使用以下材料判断成熟度：
- 当前会话已上传的简历 / 个人经历 / 项目材料 / PRD / 复盘 / 作品说明；
- 用户明确提供的文件路径；
- 当前 JobHuntBot workspace 中已有且有真实内容的经历材料。

不得为了找材料主动扫描 `Downloads` / `Desktop` / `Documents` / Home / 其他项目目录。

将当前材料分为三档：

### A｜无材料

没有足够事实可以建立经历时间线。

处理：**当前轮只给 GPT / Codex 两个选择并停止**，见 §2。

### B｜部分材料

例如只有旧简历、几段项目 bullet、单个 PRD、比赛复盘，能够看到经历轮廓，但缺背景、判断、权责、结果口径或失败边界。

处理：
1. 先读取，不让用户从头重讲；
2. 建立岗位能力证据覆盖图；
3. 对最有价值的经历做**定向补挖**；
4. 一次只问一个高信息增益问题。

### C｜完整事实母库

已经存在较完整的《个人经历.md》或等价材料，包含主要时间线、重点经历、动作、结果、证据、失败/边界。

处理：
1. 不重跑完整经历访谈；
2. 先做“岗位能力 × 已有经历”覆盖分析；
3. 如果证据已经足够，直接通过 Phase 2；
4. 如果仍有高价值缺口，只补问该缺口；
5. 对明确没有做过的能力标记缺失，不继续诱导。

**完整材料 ≠ 每个岗位能力都必须覆盖。** Phase 2 的任务是确认真实证据边界，不是把用户改造成 JD。

---

## 2. 无材料时才让用户选择 GPT / Codex

当前没有可用经历材料时，这一轮用户可见回复只做路径选择：

> 接下来进入经历挖掘阶段，你可以选一种方式：
>
> 1. **在 GPT 里完成**：我会把结合当前目标岗位核心能力的经历挖掘 Prompt 给你。你在 GPT 里一问一答完成，最后把《个人经历.md》带回来。
> 2. **直接在 Codex 里完成**：我就在当前会话一次问你一个问题，用通用事实骨架 + 当前岗位能力做定向深挖，最后生成《个人经历.md》。
>
> 回复 1 或 2 即可。

这一轮到此结束。

禁止：
- 用户还没选就直接问“你之前有过工作经历吗？实习也算。”；
- 把工作经历首问和“有旧简历也可以给我”混在同一轮；
- 默认用户选择 Codex；
- 默认把用户赶去 GPT。

如果用户不回复 1/2，而是直接上传材料或给路径，立刻重新按 §1 判断成熟度。

---

## 3. 岗位能力证据覆盖图（Phase 2 内部状态）

无论是读取已有材料，还是开始深挖，都先维护一份内部覆盖图。它不是最终简历，也不要求单独落盘。

推荐字段：

```text
岗位能力
岗位重要性
可能对应的经历
证据强度 0–3
当前已知事实
缺口类型
事实风险 / 边界
下一问价值
```

证据强度：
- `3`：真实实践 + 明确结果/验证 + 权责清楚；
- `2`：真实实践和关键动作清楚，但结果/验证较弱；
- `1`：弱相关、学习/探索、间接证据；
- `0`：当前没有证据。

### 追问优先级

优先问：
1. **Core 能力高重要性 + 已有经历很可能包含证据，但事实没挖完整**；
2. 强结果的口径、来源、对照、样本、本人/团队边界；
3. 关键判断、取舍、方案选择、验收标准；
4. 跨团队协作中的真实 ownership；
5. 可以通过一两个问题显著提升可信度的证据缺口。

降低优先级：
- 已经有 2–3 个强证据支撑的能力；
- 与目标岗位弱相关的低价值经历；
- 纯背景故事但无法增加事实理解的细节。

遇到明确 `0`：记录“无证据”，不要把用户一直问到“想起来好像做过”。

---

## 4. 通用事实骨架：所有岗位共用

对每段值得深挖的经历，内部尽量理解：

`Context / Trigger / Goal / Constraint / Problem / Decision / Action / Collaboration / Artifact / Evidence / Outcome / Failure / Reflection / Transition`

至少要知道：
- 经历与时间；
- 业务/用户场景；
- 原始问题/目标；
- 本人负责什么、不负责什么；
- 关键动作；
- 至少一个判断/取舍；
- 协作对象与产出物；
- 最终结果；
- 结果证据/数字来源；
- 未完成/失败/局限；
- 本人 / 团队 / AI 贡献边界。

这个骨架保证 `03_个人经历.md` 可以跨岗位复用，不因一次求职目标变化就推倒重来。

---

## 5. 岗位能力只负责“往哪里问深一点”

读取 `02_<行业><岗位>核心能力.md` 后，把 Core / Hard Gates / Common / Plus 映射到已有经历。

例如目标岗位强调“方案选型”，但材料只写“使用模型完成任务”，可以继续问：

> 当时你是怎么决定用这个方案的？有没有比较过别的方案，最后主要看哪些因素？

而不是：

> 你是不是做了模型选型和成本权衡？

前者在找事实，后者在提示答案。

### Anti-leading 规则

岗位能力不得变成诱导式问题。尤其禁止：
- “你这个项目是不是用了 RAG？”
- “你应该做过 A/B Test 吧？”
- “这个数字能不能写成提升 30%？”
- “为了匹配 JD，我们把这个写成主导可以吗？”

应该改成中性事实问题：
- “当时模型是否需要使用外部知识或项目资料？你怎么处理？”
- “你当时怎么比较改动前后的效果？”
- “这个结果具体怎么统计，和什么对比？”
- “这件事谁提出、谁决定、谁执行、谁验收？”

岗位能力**决定问题优先级，不决定事实结论**。

---

## 6. Codex 路径

只有用户在“无材料”分支明确选择 `2` / Codex 后，才从零开始。

第一问固定：**“你之前有过工作经历吗？实习也算。”**

- 有工作/实习：优先建立工作、实习、兼职时间线，再补校园/项目；
- 没有：直接进入课程项目、比赛、社团、个人项目、创业、研究、作品、志愿等，不继续逼问工作经历。

### 对话规则

每轮：
1. 用 1–3 句确认当前得到的关键事实；
2. 必要时指出矛盾/待核实点；
3. 对照覆盖图，**只问一个当前信息增益最高的问题**。

不是固定问卷。不同岗位、不同经历，下一问应不同。

### 一段经历何时停止

当通用事实闭环已清楚，并且当前目标岗位能从这段经历获得的高价值证据已经挖到边界，就停止。不要为了“覆盖所有 Core”继续考古。

## 7. GPT 路径

用户在“无材料”分支明确选择 `1` / GPT 后：

1. 读取 `../assets/experience-miner-prompt.md`；
2. 从 `02_<行业><岗位>核心能力.md` 提取：目标岗位、目标行业、Core 5–8、关键 Hard Gates / Common（仅必要项）；
3. 把这些内容填入 Prompt 的“岗位定向上下文”；
4. 把**填好后的完整 Prompt**交给用户；
5. 用户在 GPT 一问一答完成后带回《个人经历.md》；
6. 当前 Phase 2 暂停在 Gate B。

不要把整份 JD/所有研究材料塞进 Prompt，只给决定追问方向所需的能力摘要。

---

## 8. 事实可信度与数字核验

- `A 强事实`：上线/真实使用/系统或财务数据/负责人验收/明确奖项等；
- `B 边界事实`：历史对照、小样本、人工统计、内部测试、定性反馈、合理估算；
- `C 背景事实`：动机、探索、失败、转折、兴趣来源；
- `U 未确认`：记忆模糊、来源不明、材料冲突。

`U` 不得写成简历强结论。

亮眼数字至少确认：
- 口径；
- 来源；
- 时间范围；
- 对照基线；
- 本人还是团队；
- 是否估算。

用户只记得“大概一半”就保留“约 50%”，不要制造 47.3% 这种小数点 cosplay。

---

## 9. AI / 团队贡献边界

使用 ChatGPT、Codex、Claude、Gemini、Cursor、Agent 等时分开记录：

用户可能负责：目标定义、业务判断、约束、方案选择、取舍、验收、反馈、迭代要求。

AI/工具可能负责：代码生成、初版方案、文案、设计、批处理、技术实现建议。

团队项目同时确认：谁提出、谁决定、谁执行、谁验收。

禁止为了 STAR 完整性补：数字、结果、用户量、上线、测试、团队规模、AI 深度、协作对象。

---

## 10. 输出 `03_个人经历.md`

`03_个人经历.md` 是**跨岗位复用的事实母库**，不是只为当前 JD 写的简历素材。

应保留：
- 主要时间线；
- 重点经历的通用事实闭环；
- 真实结果与证据等级；
- 失败/未完成；
- 本人/团队/AI 边界；
- 当前复盘。

当前目标岗位决定哪些经历挖得更深，但不要删除暂时与当前岗位弱相关、未来仍可能有价值的真实经历。可以轻量记录，不必同等深挖。

已有 `03_个人经历.md` 时应**增量更新**，不要因切换岗位整份重写成另一种人格。

---

## 11. Gate B

Gate B 通过不等于“所有 Core 能力都被凑齐”。通过条件：
- 最可能进入简历的 2–5 段重点经历有真实事实闭环；
- 强结果的证据边界已知；
- 本人/团队/AI ownership 可解释；
- 对当前岗位的主要强证据、弱证据、明确空白已经识别；
- 高价值可补事实已补问，剩余缺口可以诚实进入 Phase 3 证据矩阵。

核心能力没有证据时，正确结果是“0 / 缺口”，不是继续盘问直到出现一个好看的答案。
