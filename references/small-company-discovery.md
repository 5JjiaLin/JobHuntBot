# Small & High-Quality Company Discovery｜小而美企业可执行搜索 SOP

本文件只负责 **Phase 1 企业树中的“小而美 / 早期优质企业”发现与验证**。它不是独立求职流程，也不负责简历、具体岗位匹配或投递。

## 1. Owns

目标不是“找小公司”，而是找到：

> **规模相对较小，但业务真实、细分竞争力明确、存在当前成长信号，并且对目标岗位有实际价值的公司。**

核心规则：

```text
发现信号 ≠ 优质结论
```

任何公司都必须经过候选发现、验证和 Quality Gate 后，才能进入企业树的“小而美”主名单。

## 2. Inputs

必需：
- 目标行业；
- 目标岗位。

按需获取，不要为了形式主义一次性追问：
- 目标城市 / 地区；
- 公司规模偏好；
- 明确排除项；
- 是否接受早期创业公司。

地区只有在会显著改变企业发现结果时才作为搜索边界。

## 3. Exclusions｜本模块不负责

不要在这里做：
- 判断用户本人是否适合某家公司；
- 针对用户经历计算具体岗位匹配分；
- 写简历或改简历；
- 查当前具体职位并完成 S / A / B 排序；
- 创建投递进度表；
- 直接投递或联系招聘方。

这些属于后续简历、Phase 4 岗位匹配与 Phase 5 投递工作台。

# 可执行搜索流程

## Step 1｜确定搜索边界并拆细分赛道

### 输入
- 目标行业；
- 目标岗位；
- 必要时的城市 / 地区。

### 动作
1. 把目标行业拆成 3–8 个对求职有实际意义的细分赛道；
2. 只保留与目标岗位可能有真实工作空间的方向；
3. 生成后续搜索要使用的行业同义词、英文名和细分关键词。

示例，AI 行业可以拆为：

```text
大模型 / AI Agent / AI SaaS / AI 内容 / AI 电商 / 开发者工具 / AI 基础设施 / 行业 AI
```

### 停止条件
- 细分赛道已能覆盖该行业主要业务形态；
- 继续拆分只会变成产品级或公司级碎片。

### 输出
`搜索边界 + 细分赛道 + 同义搜索词`

---

## Step 2｜官方资质 / 政府产业名单发现

### 输入
Step 1 的行业、细分赛道、地区和年份。

### 搜索动作
按行业与地区组合搜索，示例公式：

```text
<城市> <当前/最近年份> <行业> 专精特新 名单
<城市> <当前/最近年份> 专精特新小巨人 名单
<城市> <当前/最近年份> <行业> 瞪羚企业
<城市> <当前/最近年份> 潜在独角兽 名单
<行业> 制造业单项冠军 企业
<产业园/高新区> <行业> 重点企业
```

优先来源：
- 工信；
- 科技；
- 发改；
- 地方政府；
- 官方园区 / 高新区；
- 官方协会或政府发布平台。

第三方转载只做发现，不替代官方证据。

### 停止条件
- 已覆盖该地区 / 行业最主要的官方名单来源；
- 新搜索结果主要是重复转载或重复企业。

### 输出
候选池 A：

```text
企业全称 | 细分赛道 | 发现来源 | 发现信号 | 来源日期
```

注意：`专精特新 / 小巨人 / 瞪羚 / 独角兽` 只能让企业进入候选池，不能直接升级为“小而美”。

---

## Step 3｜行业 / 区域榜单发现

### 输入
Step 1 的行业、细分赛道和地区。

### 搜索动作
示例公式：

```text
<细分赛道> 企业 TOP / 排行榜 / 榜单
<城市> <行业> 百强 / TOP50
<城市> 民营企业百强
<城市> 科技企业百强
<产业园> 重点企业
<行业协会> 会员 / 标杆 / 龙头 企业
```

优先观察：
- 有方法说明和明确来源的行业榜单；
- 官方 / 行业协会 / 产业园榜单；
- 榜单中后段但有真实业务的低知名度公司。

不要假设“榜单第 20–100 名一定更适合求职”；排名只用于发现，不是岗位价值结论。

### 停止条件
- 主要细分赛道均有榜单或区域来源覆盖；
- 新结果主要重复已有候选或来源质量明显下降。

### 输出
候选池 B：

```text
企业全称 | 细分赛道 | 榜单 / 区域来源 | 排名或发现信号 | 来源日期
```

---

## Step 4｜创投 / 产业资本渠道发现

### 输入
目标行业、细分赛道、必要时的地区。

### 搜索动作
优先使用适合该行业的创投 / 产业资本来源，例如：
- IT 桔子；
- 36氪项目 / 融资信息；
- 烯牛数据；
- 投中网；
- 知名 VC / CVC 官方 Portfolio；
- 地方产业基金投资名单。

示例搜索：

```text
<细分赛道> 融资 <当前/最近年份>
<城市> <行业> A轮 / B轮 / C轮 公司
<VC/CVC 名称> <行业> portfolio
<产业基金> <行业> 投资企业
```

B 轮及以后可作为“业务可能更成熟”的发现信号，但**不是硬门槛**。A / A+ 等早期公司如果已有真实产品、客户、增长和岗位价值，也可以继续验证。

### 停止条件
- 主要资本来源和近期融资信息已覆盖；
- 新结果主要是旧融资、重复新闻或缺乏当前业务证据的公司。

### 输出
候选池 C：

```text
企业全称 | 细分赛道 | 轮次 / 资本来源 | 最近融资时间 | 发现信号
```

融资只是一种成长信号，不等于模式成熟，也不等于值得求职。

---

## Step 5｜行业专属渠道补充发现

前三类来源是通用入口；本步骤必须根据行业选择真正有解释力的来源，防止只靠融资和资质漏掉行业内强公司。

| 行业 | 优先补充来源 |
|---|---|
| AI / 互联网 | AI 企业榜、代表产品、开发者生态、产业园、GitHub / Product Hunt 等产品与开发者信号 |
| 制造 / 工业 | 专精特新、小巨人、单项冠军、供应链地位、产业集群、客户交付 |
| 游戏 | 产品榜单、版号 / 发行记录、活跃产品、研发 / 发行能力 |
| 电商 / 跨境 | 品牌 / 平台榜、跨境企业榜、供应链、海外业务、品牌能力 |
| 机器人 | 量产 / 交付、客户案例、机器人产业榜、融资、场景落地 |
| 生物医药 | 管线阶段、临床进展、专利 / 技术平台、产业园、专业投资机构 |
| 文创 / 设计 / 传媒 | 专业奖项、行业榜单、标杆客户、地方文化产业名录 |

若行业不在表中，先判断什么证据最能证明该行业的“业务真实 + 细分竞争力”，再设计搜索词。

### 覆盖要求
- 正常情况下至少使用 **2 类互补的有效来源** 完成候选发现；
- 不要求机械跑满官方 / 榜单 / 创投 / 行业专属四类；
- 跳过某类来源时，内部记录“为什么对该行业解释力低 / 不可得”。

### 停止条件
- 行业最有解释力的补充来源已覆盖；
- 新结果主要与 A / B / C 候选池重复。

### 输出
候选池 D + 本行业的搜索覆盖说明。

---

## Step 6｜候选池合并与企业实体去重

### 输入
候选池 A + B + C + D。

### 动作
1. 按企业全称、官网主体、品牌与工商主体关系去重；
2. 同一企业多渠道出现时合并发现证据，不重复新增；
3. 品牌名与公司主体不确定时标 `Unknown`，不要擅自合并；
4. 保留每条发现来源，后续可用于交叉验证。

### 停止条件
- 候选企业实体唯一；
- 重复来源已合并；
- 主体冲突已标记。

### 输出
统一候选池：

```text
公司 | 细分赛道 | 发现渠道 | 发现信号 | 初始证据状态
```

---

## Step 7｜业务真实性初筛

本步骤只做快速淘汰，不对所有候选进行同等深度研究。

### 搜索动作
对每家公司优先搜索 / 打开：

```text
<企业名> 官网
<企业名> 主营业务
<企业名> 产品
<企业名> 客户 / 案例
```

优先证据：
- 公司官网；
- 产品页；
- 客户案例；
- 官方新闻；
- 官方工商 / 产业来源。

确认：
1. 公司是否仍在运营；
2. 当前主要做什么；
3. 目标行业是否仍是核心业务；
4. 是否存在真实产品 / 服务 / 客户场景。

### 快速排除
- 已明显停止经营；
- 已转型离开目标行业；
- 只有概念，没有可验证产品 / 服务；
- 主营业务与目标行业明显不相关；
- 关键事实严重冲突且无法核验。

### 停止条件
每个候选已得到 `保留 / 排除 / 待核验` 的初筛状态。

### 输出
进入深度验证的候选池 + 初筛排除记录。

---

## Step 8｜公司质量深度验证

只对 Step 7 保留下来的公司做深度验证。

### 8.1 公司规模
规模只用于描述，不单独决定质量。记录区间即可：
- `<100`；
- `100–500`；
- `500–1000`；
- `1000+`；
- `Unknown`。

### 8.2 业务质量
优先证据：
- 当前产品 / 服务持续运营；
- 公开客户案例；
- 明确商业化路径；
- 用户 / 客户规模；
- 量产 / 交付 / 上线记录；
- 可验证收入、订单或市场采用信号。

### 8.3 细分行业地位
优先证据：
- 权威行业榜单；
- 细分市占 / 排名；
- 标杆客户；
- 头部供应链位置；
- 代表性产品；
- 行业协会 / 官方产业认定。

### 8.4 成长信号
优先看当前：
- 新融资；
- 新产品 / 新业务；
- 客户增长 / 市场扩张；
- 招聘扩张；
- 新区域 / 海外扩张；
- 产能 / 交付扩大。

### 8.5 外部背书
例如：
- 当前有效官方资质；
- 知名 VC / CVC / 产业基金；
- 权威行业榜单；
- 标杆客户；
- 上市公司 / 大型集团战略合作。

外部背书是加分项，不是业务质量替代品。

### 停止条件
五个维度已有足够证据支持判断，或缺失项已明确标为 `Unknown`。

### 输出
公司质量证据表。

---

## Step 9｜目标岗位价值验证

这是求职场景必须单独验证的维度。

### 搜索动作
优先看：
- 官方招聘页；
- 当前 / 历史对应职能招聘记录；
- 团队 / 产品组织介绍；
- 核心产品与目标岗位的关系。

示例搜索：

```text
<企业名> 招聘
<企业名> <目标岗位>
site:<公司官网域名> <目标岗位>
```

本步骤不是 Phase 4，不要求现在一定存在可投岗位。这里只判断：
- 目标岗位是否与核心业务直接相关；
- 是否存在真实产品 / 业务问题可做；
- 公司是否有对应职能或招聘记录；
- 该岗位是否可能获得完整的业务 ownership。

不得仅凭“创业公司一般能做得更多”这种想象打高分。

### 输出
`目标岗位价值：High / Medium / Low / Unknown` + 证据。

---

## Step 10｜Evidence Status 与 Freshness

每个关键判断必须标记证据状态：
- `Verified`：有直接、可靠来源支持；
- `Likely`：有多条间接证据，但缺直接确认；
- `Unknown`：目前没有足够证据；
- `Conflicting`：来源互相冲突，需要继续核验。

成长性证据必须区分时效：
- 近 12 个月：强当前信号；
- 12–36 个月：辅助信号；
- 超过 36 个月：历史背景，不得作为主要当前成长证据。

官方资质同样区分：
- 当前有效；
- 历史获得；
- 无法确认。

例如“2022 年完成 B 轮”在 2026 年只能算历史融资背景，不能单独证明当前仍高速成长。

## Step 11｜Quality Gate

内部使用 5 个维度辅助比较：

| 维度 | 权重 | 判断重点 |
|---|---:|---|
| 业务质量 | 25 | 产品 / 服务是否真实持续、商业模式和客户场景 |
| 细分行业地位 | 25 | 是否在某个垂直领域具备可验证竞争力 |
| 成长信号 | 20 | 近期融资、扩张、产品、客户、招聘等 |
| 外部背书 | 15 | 官方资质、资本、榜单、标杆客户 |
| 目标岗位价值 | 15 | 目标岗位与核心业务关联度、工作空间 |

参考解释：
- `70–100`：小而美重点候选；
- `50–69`：候选，证据或质量仍需补充；
- `<50`：不进入企业树主名单。

### Evidence Confidence
同时输出：
- `High`：关键结论大多为 Verified，且来源互相一致；
- `Medium`：核心结论基本成立，但仍有若干 Likely / Unknown；
- `Low`：关键信息缺失、过期或互相冲突。

### 入主名单规则
原则上需要：

```text
Quality Score >= 70
AND
Evidence Confidence = High / Medium
```

高分但 `Low Confidence` 不得直接列为重点小而美。

### 评分纪律
- 分数是排序辅助，不是假装精确的投资评级；
- `Unknown` 维度不得凭印象给高分；
- 单一强信号不能代替其他维度；
- 不为了达到 70 分而人为抬分。

---

## Step 12｜禁止单信号升级

以下任一条件 **单独出现** 时，只能进入候选池，不得直接判为“小而美”：
- 专精特新 / 高新技术企业；
- 完成融资；
- 被媒体报道；
- 出现在榜单；
- 员工人数较少；
- 有知名投资机构；
- 官网写着“行业领先”。

至少要形成“业务质量 + 细分竞争力 + 岗位价值”的组合证据。

## 14. Search Coverage 完成标准

“小而美搜索完成”不是看公司数量，而是看：

```text
Search Coverage
+
Evidence Quality
+
Explicit Limitations
```

正常情况下：
- 至少使用 2 类互补且对当前行业有效的发现来源；
- 候选完成实体去重；
- 主名单公司完成业务真实性、公司质量、岗位价值、Evidence Status / Freshness、Quality Gate；
- 样本不足时有明确搜索覆盖和排除原因。

行业确实很小时，可以只有少量主名单公司。**搜索完整但结果少，可以通过；没搜完整却凑够数量，不通过。**

## 15. Integration with JobHuntBot

Phase 1：

```text
目标岗位 + 已确认行业
→ 小而美可执行搜索 SOP
→ Quality Gate
→ 写入 01_企业树.md 的“小而美 / 早期优质”分支
```

Phase 4：

```text
读取 01_企业树.md
→ 进入这些公司的官方招聘渠道
→ 查当前真实岗位
→ Hard Gate
→ Match Score
→ S / A / B / blocked
```

本模块只回答“哪些公司值得进入企业树”，Phase 4 才回答“它现在有没有值得用户投的具体岗位”。

## 16. Failure Rules

出现以下情况时不要硬凑结果：
- 行业太小，候选数量不足；
- 大部分证据为多年以前；
- 公司已经明显转型离开目标行业；
- 公司主体 / 品牌关系无法确认；
- 只有融资 / 资质 / 榜单而缺少真实业务证据；
- 目标岗位与核心业务关系无法证明；
- 来源互相冲突且无法消解。

这些情况应保留为 `候选 / 待核验 / 排除 / 样本限制`，而不是为了填满企业树制造结论。
