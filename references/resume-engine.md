# Resume Engine｜核心能力 × 真实经历 → 正式简历

本阶段不是“把经历写得更厉害”，而是**按岗位重要性排序用户真实拥有的能力证据，并生成可直接投递的简历**。

先读：
- `02_<行业><岗位>核心能力.md`
- `03_个人经历.md`
- `references/evidence-rules.md`
- `references/resume-format.md`

## 1. 输出 `04_证据矩阵.md`

```md
| 岗位能力 | 重要性 | 对应经历 | 证据强度 0-3 | 结果/证据 | 风险/边界 | 简历处理 |
```

证据强度：3=真实实践+明确结果/验证；2=真实实践且动作清楚；1=弱相关/学习探索；0=没有。0 不写成具备；1 弱化；2–3 优先进入正文。

## 2. 经历选择

按：Core 相关度 → 结果强度 → 覆盖能力数 → 证据可信度 → 面试可追问性排序。不要为了“丰富”把弱项目塞满一页。

## 3. STAR / 反向 STAR

STAR 是组织逻辑，不在正文写 S/T/A/R。强结果用 `R → A → T/S`；判断过程重要时用标准 STAR。Action 必须体现发现问题、拆解、为什么选方案、取舍、协作、验收，而不是动作日志。

## 4. 岗位适配

- 产品/项目：用户/业务问题、需求拆解、优先级、功能/流程、取舍、协作、验收、结果。
- 运营/增长/市场/销售：目标人群、渠道策略、转化链路、ROI/营收/留存、复盘。
- 数据/策略：业务问题、指标、数据、方法、结论、决策影响。
- 技术/工程：技术问题、方案、实现、性能/稳定性、工程结果。
- 设计/内容：用户/内容目标、方案探索、关键取舍、作品与反馈。
- 综合职能：问题分析、主动性、协作、项目结果、商业判断。

标签随岗位动态调整，不把“AI 产品能力”硬编码到所有简历。

### 产品 / AI 产品附加规则

当目标岗位属于产品经理时，正文尽量证明真实做过的：
- 用户/业务需求拆解；
- 功能规划与优先级；
- 产品流程、交互与功能边界；
- 需求文档/功能说明/验收标准（真实做过才写）；
- 数据或人工验收；
- 与设计、研发、业务协作；
- 上线/验证后的迭代。

当目标岗位属于 AI 产品经理时，在传统产品基本功之上再证明真实存在的 AI 增量能力：
- AI 适用性判断与模型能力边界；
- 模型/方案选型；
- Prompt / Skill / Workflow；
- RAG / Agent / 多模态（做过什么写什么）；
- AI 效果评测、Bad Case、回归验证；
- 成本 / 质量 / 延迟权衡；
- AI Coding 快速原型与验收。

原则：`AI PM = 产品基本功 + AI 增量能力`，不能用一堆模型名替代产品证据。

### PRD 与协作

PRD 是产物，不是凭空能力标签。正式写过 PRD 才写 PRD；如果实际做的是功能定义、流程、交互说明、验收标准、需求边界，就写这些真实动作。

跨团队协作必须落到具体证据：与设计对齐交互、与研发对齐接口/验收、与业务确认目标、与运营复盘结果等。

## 5. 结果与真实性

结果证据优先：业务结果 → 用户结果 → 质量/工程结果 → 验证结果。没有更高层结果就用下一层真实证据，不补一个“更像商业成果”的数字。

审计 `主导/独立/推动/负责/设计/搭建/上线/全链路/全面替代` 等权责词，确认谁提出、谁决定、谁执行、谁验收。

任何亮眼结果都保留可信度锚点：对照口径、样本范围、质量是否下降、是否估算。

## 6. 标准简历格式

默认严格按 [resume-format.md](resume-format.md)；模板为 `../assets/resume-template.docx`。

核心结构：

```text
姓名 + 右上照片位
目标岗位｜方向
届别/学历｜到岗/实习时长
手机｜邮箱
个人简介
实习经历
项目经历
核心能力
教育背景
```

经历优先按项目组织，每条 bullet 用有意义的粗体语义标签开头，例如“业务结果：”“需求拆解与产品设计：”“验证与结果：”。具体标签按岗位改变。

## 7. 一页优先

超过一页时先删：重复动作、技术流水账、弱项目、空泛技能；其次压缩措辞和段距。不要先无限缩字体，也不要删最强结果/Core 证据。

## 8. 输出 `05_简历.md`

这是内容真源：成稿，不输出分析过程代替简历。

## 9. 输出 `05_简历.docx`

当前环境具备可靠 DOCX 编辑能力时，基于 `assets/resume-template.docx` 生成正式 Word 版：
- 保留模板视觉层级与右上照片空位；
- 不写入模板作者真实个人信息；
- 检查是否一页；
- 能渲染时必须渲染检查无溢出、遮挡、错位后再视为完成。

若当前 Agent 确实没有 DOCX 编辑能力，明确标记该产物未生成，不伪造文件，并保留 `05_简历.md` 作为可转换源。

## 10. 输出 `06_简历审计.md`

至少包含：岗位能力覆盖、强/弱/空白证据、事实数字风险、权责风险、AI 贡献边界、HR 5 秒测试、面试追问风险、最终结论 `pass / revise / blocked`。

### HR 5 秒测试
每段应快速看出：这是什么、为什么做、本人做了什么、结果是什么、为什么与岗位有关。

### 面试追问测试
数据怎么算、为什么选方案、替代方案、本人 vs 团队、谁拍板、怎么验收、怎么证明、最大失败、重做怎么改。答不上来就降低表述，不发明答案。

## Gate C

只有 `pass` 或完成 `revise` 后才能进入当前岗位匹配。`blocked` 时说明缺失事实，不强行继续。
