# Role Research｜行业定位、企业树与 Benchmark JD 能力模型

本文件只负责 Phase 1。目标不是“列一些公司”，而是先确定**岗位所在行业语境**，再建立完整企业树，并用 5 家标杆企业的当前完整 JD 建立可追溯能力标准。

## 1. 输入

首个必需输入只有：目标岗位。

先扩展同岗位族搜索词：目标岗位名、常见英文名、行业内同义名称。相邻岗位不能替代目标岗位样本，例如算法工程师 JD 不能替代产品经理 JD。

## 2. 岗位 → 行业识别

在建立企业池前，先研究该岗位主要存在于哪些行业 / 业务形态。

输出给用户时只列有实际求职意义的主要行业，并为每个行业给一句岗位侧重点差异，例如：

```text
互联网/内容：偏用户增长、内容生态、平台协作
AI/SaaS：偏模型能力边界、AI Workflow、B 端/工具产品
电商/零售：偏交易链路、供给、转化与商业化
机器人：偏软硬件协同、场景落地、交付
```

然后只问一个核心分叉：`你这次主要想进入哪个行业？`

用户已明确“AI 行业产品经理”之类行业信息时，不重复询问。

行业确认后初始化 / 复用 `workspace/<slug>/`，把 `target_industry` 写入当前工作区配置（环境支持时）。

## 3. 构建企业树：必须执行三个独立 discovery pass

读取 [company-tiering.md](company-tiering.md)。企业层级相对于**已确认行业 + 目标岗位**判断，不只按员工人数、上市状态或知名度。

企业树固定三层：
- 头部 / 标杆企业；
- 中厂 / 成长型企业；
- 小而美 / 早期优质企业。

**不得只做一次综合公司搜索，再让 Agent 自行把结果分成大 / 中 / 小。** 三层必须分别执行对应的发现流程。三个 discovery pass 全部完成后，再做企业实体去重与分层复核。

### Pass 1｜头部 / 标杆企业 discovery

目标：建立目标行业中最有代表性的标杆公司池，并为后续 5 家 Benchmark JD 提供候选。

#### 输入
- 已确认行业；
- 目标岗位；
- 必要时的地区限制。

#### 搜索动作
1. 搜索行业头部、平台型企业、代表产品、市场地位、成熟商业化公司；
2. 对候选确认当前主营业务、行业地位、业务体量、组织成熟度和目标岗位相关性；
3. 记录官方招聘入口；
4. 明显只靠品牌知名度、但目标岗位与核心业务关联弱的公司，不应仅凭名气列为 Benchmark 首选。

#### 停止条件
- 已覆盖该行业主要标杆公司；
- 继续搜索主要出现重复结果；
- 已有足够代表不同细分方向的头部候选。

#### 输出
头部 / 标杆候选池。目标范围通常 8–15 家，行业过小时允许更少；数量不是硬 KPI。

### Pass 2｜中厂 / 成长型企业 discovery

目标：找到成熟成长公司、细分头部、上市 / 独角兽 / 高质量规模化企业，但整体行业影响力或组织规模低于头部标杆的公司。

#### 输入
- 已确认行业；
- 目标岗位；
- Pass 1 已发现公司，用于去重和相对分层。

#### 搜索动作
1. 可用 `../assets/company-seeds.md` 作为候选发现入口；
2. 补充搜索细分赛道头部、成长型公司、独角兽 / 上市成长企业、代表产品公司和招聘活跃企业；
3. 每家公司重新验证当前主营业务、行业位置、规模、业务成熟度、组织成熟度、招聘活跃度和目标岗位相关度；
4. 验证后允许升级为头部、保留为中厂、降为小而美 / 候选，或排除。

#### 停止条件
- 主要细分赛道均有覆盖；
- seeds 和实时发现结果已完成验证；
- 继续搜索主要出现重复或低相关公司。

#### 输出
中厂 / 成长型候选池。目标范围通常 10–25 家，行业过小时允许更少；不得为了数量把证据弱的公司硬塞进来。

### Pass 3｜小而美 / 早期优质企业 discovery

目标：发现大众知名度较低，但业务真实、细分竞争力明确、存在成长信号，并且对目标岗位有实际价值的公司。

**执行本 Pass 前 MUST 读取 [small-company-discovery.md](small-company-discovery.md)，并按其中的可执行搜索 SOP 完成。**

最少必须经历：

```text
搜索边界
→ 多渠道候选发现
→ 候选池合并 / 企业实体去重
→ 业务真实性初筛
→ 公司质量深度验证
→ 目标岗位价值验证
→ Evidence Status / Freshness
→ Quality Gate
→ 入树
```

专精特新、融资、VC、榜单、媒体报道、员工人数等单一信号只用于发现，不得直接判为“小而美”。

#### 输出
小而美 / 早期优质主名单 + 候选 / 待核验名单 + 搜索覆盖与样本限制。

## 4. 企业树合并、去重与分层复核

三个 Pass 都执行完成后：

1. 合并全部候选；
2. 同一企业多渠道发现时合并证据，不重复新增；
3. 按 `company-tiering.md` 复核最终层级；
4. 记录每层的发现路径、候选数、入树数、排除数和主要排除原因；
5. 数量不足时记录样本限制，不补公司。

每家公司至少记录：

```text
公司名 | 层级 | 细分赛道 | 当前主营业务 | 目标岗位相关性 | 官方招聘入口 | 关键证据 | 验证日期 | 置信度
```

### 企业发现覆盖记录

`01_企业树.md` 中必须加入：

```md
## 企业发现覆盖记录
| 层级 | 已执行发现路径 | 候选数 | 入树数 | 排除数 | 主要排除原因 / 样本限制 |
```

这张表用于区分“确实搜索后没有找到足够样本”和“根本没有执行该层搜索”。

## 5. 企业树完成门槛

只有同时满足以下条件，才能开始 Benchmark JD：
- 头部 / 标杆已完成独立 discovery；
- 中厂 / 成长型已完成独立 discovery；
- 小而美 / 早期优质已按 `small-company-discovery.md` 完成独立 discovery 与 Quality Gate；
- 三层候选已合并去重并完成分层复核；
- `01_企业树.md` 已写入三层结果和企业发现覆盖记录；
- 某层样本不足时，已记录搜索来源、主要排除原因和限制。

**找到 5 家头部企业不代表企业树完成。** 未满足企业树完成门槛，不得提前进入 Benchmark JD。

## 6. 选择 5 家 Benchmark 企业

企业树完成后，从头部 / 标杆层选择 **5 家不同企业**，要求：
- 同一目标行业；
- 目标岗位族有代表性；
- 企业在该行业具备标杆意义；
- 能找到当前或近期可验证的完整官方 JD。

避免 5 家都来自同一细分业务导致偏差。若行业确实只有少量代表企业，明确样本限制。

## 7. Benchmark JD 规则

每家企业选 1 份最有代表性的目标岗位完整 JD，共 5 份。

浏览器可用时必须实际打开官方招聘站 / 官方 ATS 页面读取正文。搜索摘要只做发现；第三方完整 JD 只有在官方页面确实不可访问时作为降级证据，并标记来源等级。

每份记录：

```text
公司：
岗位名称：
岗位 URL：
来源：官方 / 官方 ATS / 第三方降级
验证时间：
业务目标：
核心职责：
Hard Gates：
能力要求：
工具/技术：
经验/学历：
Plus：
业务场景：
```

同一公司重复 / 镜像岗位不重复计数。

## 8. 能力归一化

按语义归一，不机械数关键词。例如：
- 需求洞察 / 用户需求分析 / 场景挖掘 → `需求发现与拆解`
- 跨团队推进 / 协同研发设计 / 项目推动 → `跨团队协作与推进`

每个能力保留来源 JD。

### 频率作为辅助证据

- 5/5：近乎普遍要求；
- 4/5：高频核心；
- 2–3/5：Common；
- 1/5：公司特异或 Plus 候选。

频率不是唯一规则。若某项虽然仅 3/5，但持续出现在关键职责并构成岗位产出的前置能力，可以进入 Core，并说明理由。

## 9. 能力分层

最终输出：
- **Core 5–8**：岗位主要产出需要的核心能力；
- **Hard Gates**：不满足可能无法投递 / 明显降级的硬门槛；
- **Common Skills**：常见但非普遍；
- **Plus**：明确的 preferred / 加分项；
- **Company Differences**：5 家标杆企业的明显差异；
- **Resume Must Prove**：后续简历必须拿经历证明什么。

## 12. Gate A

必须同时满足：
- 目标行业已确认；
- 企业树完成门槛已通过；
- 5 家 Benchmark 企业尽量不同且具代表性；
- 5 份 JD 已实际读取完整正文，受限样本显式标记；
- Core / Hard Gate / Common / Plus 有来源证据；
- 小而美不是由单一融资 / 资质 / 榜单信号直接升级。

否则继续研究或明确阻塞，不进入“确定版简历”。
