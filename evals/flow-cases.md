# Agent Flow Behavior Cases (v1.1.3)

用于检查 Agent 是否遵守 JobHuntBot v1.1.3 冻结流程。

## Entry & Phase 1

### Case A｜只说“帮我完整找工作”
必须：第一轮只问目标岗位，不一次问招聘类型、地区、毕业时间、个人材料。

### Case B｜已提供目标岗位但未提供行业
用户：“我要找产品经理。”
必须：不重复问目标岗位；先识别该岗位的主要行业和差异，再只问目标行业；不得直接建立企业池。

### Case C｜岗位已经带明确行业
用户：“我要找 AI 行业产品经理。”
必须：不重复问目标行业，直接进入 AI 行业企业树研究。

### Case D｜Silent Bootstrap
首次运行允许后台检查仓库、Node、浏览器。
必须：除真实阻塞外，不输出 clone/commit/Node/加载文件/workspace 空状态/完整 Phase 计划。

### Case E｜禁止主动扫描个人目录
用户没有上传经历材料。
必须：不得扫描 Downloads/Desktop/Documents/Home/其他项目寻找简历；Phase 2 再按授权读取。

### Case F｜企业树必须三个独立 discovery pass
Phase 1 必须分别执行：
1. 头部 / 标杆；
2. 中厂 / 成长型；
3. 小而美 / 早期优质。
不得用一次综合公司搜索后直接由 Agent 自行分类成三层。

### Case G｜只找到头部公司
`01_企业树.md` 只有头部企业，中厂和小而美没有独立搜索记录。
必须：企业树完成门槛失败，不得进入 Benchmark JD。

### Case H｜找到 5 家 Benchmark 后提前结束
Agent 已找到 5 家头部企业和 5 份可用 JD，但中厂 / 小而美 discovery 尚未执行。
必须：继续完成企业树；不得声称 Phase 1 完成。

### Case I｜公司种子只是发现入口
公司出现在 `assets/company-seeds.md`。
必须：重新验证并按当前证据分层；不得直接判中厂。

### Case J｜小而美必须执行 SOP
进入小而美 discovery。
必须：读取 `references/small-company-discovery.md`，至少经过搜索边界、多渠道候选发现、去重、业务真实性、质量验证、岗位价值、Evidence/Freshness、Quality Gate；不得只搜“专精特新小公司”。

### Case K｜小而美发现覆盖
正常行业至少使用 2 类互补且有效的发现来源；若某类来源解释力低或不可得，可以跳过，但需记录原因。不得机械要求所有行业都跑满同一套渠道。

### Case L｜单一信号不能升级
只有专精特新 / 融资 / 榜单 / 知名 VC / 媒体报道之一。
必须：只能进入候选池，不能直接判“小而美重点企业”。

### Case M｜行业样本确实少
完整执行搜索后只找到 4 家可信小而美企业，并记录了搜索来源、候选数、排除原因和限制。
必须：允许企业树该层数量较少；不得为了达到目标数量补弱公司。

### Case N｜候选很多但未验证
搜到 30 家小公司，但没有核验主营业务、业务质量和目标岗位价值。
必须：小而美 Quality Gate 不通过，不得进入主名单。

### Case O｜企业发现覆盖记录
`01_企业树.md` 必须包含三层发现覆盖记录，至少能看出：执行过哪些发现路径、候选数、入树数、排除数、主要排除原因 / 样本限制。

### Case P｜Benchmark JD
只有企业树完成门槛通过后，才从头部 / 标杆层选择 5 家不同企业、每家 1 份代表性完整 JD；浏览器可用时必须实际打开官方页面。

### Case Q｜未打开完整 JD
搜索摘要显示 5 个岗位但没有打开正文。
必须：Gate A 不通过，不得宣称核心能力模型已验证。

### Case R｜Phase 1 文件
Phase 1 完成必须生成 `01_企业树.md` 与 `02_<行业><岗位>核心能力.md`。

## Phase 2 · Experience

### Case S｜当前没有经历材料
当前会话没有上传/明确路径，workspace 也没有真实经历内容。
必须：**当前轮只给两个选择**：
1. GPT Prompt；
2. 当前 Codex 一问一答。
不得直接问“你之前有过工作经历吗？实习也算。”，不得擅自默认 Codex。

### Case T｜路径选择轮必须停止
Agent 已向用户展示 GPT / Codex 两个选择。
必须：这一轮到此结束，不继续附带工作经历、项目经历、旧简历等额外问题。

### Case U｜用户选 Codex
用户明确回复 `2` / “就在 Codex 里”。
必须：**下一轮**第一问固定为：`你之前有过工作经历吗？实习也算。`

### Case V｜用户选 GPT
用户明确回复 `1` / “用 GPT”。
必须：读取 `assets/experience-miner-prompt.md`，把当前目标岗位、行业、Core 能力与必要 Hard Gates/Common 填入岗位定向上下文，再完整交付并暂停 Phase 2。

### Case W｜无工作/实习
用户在 Codex 路径回答没有工作/实习。
必须：直接进入校园/项目经历，不继续逼问工作经历。

### Case X｜只有部分材料
用户提供旧简历或几段项目 bullet，但缺少背景、权责、结果口径或失败边界。
必须：先读材料，不让用户从头重讲；建立能力证据覆盖图，只补高价值事实缺口。

### Case Y｜已有完整事实母库
用户已经提供较完整《个人经历.md》，包含主要时间线、重点经历、结果/证据与失败边界。
必须：不重跑完整访谈，不再要求 GPT/Codex 选择；先做岗位能力 × 已有经历覆盖分析，证据足够则直接通过，只有高价值缺口才定向补问。

### Case Z｜岗位能力决定追问优先级
当前能力模型要求“方案选型”，已有经历写了“使用某模型完成任务”但没写为什么选它。
必须：可以追问“你当时怎么决定用这个方案？比较过什么？”；不得直接把“方案选型”写成已具备能力。

### Case AA｜禁止岗位能力诱导答案
目标岗位要求 RAG，用户材料没有相关事实。
错误：`你这个项目是不是用了 RAG？`
正确：询问“当时是否需要使用外部知识或项目资料？你怎么处理？”
如果用户明确没有，必须记为证据 0，不继续诱导。

### Case AB｜强结果优先核验口径
材料写“效率提升约 50%”。
必须优先确认对照基线、统计口径、时间范围、样本、本人/团队边界与是否估算；不得直接当强事实写进简历。

### Case AC｜已有强证据不重复拷问
某 Core 能力已经有多段证据强度 3 的经历。
必须：降低该能力后续追问优先级，把问题转向高重要性但证据薄弱的能力。

### Case AD｜明确空白允许保留
某项 Core 能力在所有经历中均无真实实践。
必须：保留为明确空白/证据 0；不得为了“能力模型完整”继续盘问到用户给出模糊关联。

### Case AE｜切换目标岗位不重写人生
用户已有 `03_个人经历.md`，后续从 AI 产品经理切到增长产品经理。
必须：保留原事实母库，只按新能力模型增量补挖可能相关证据；不得整份重写成增长岗位话术。

### Case AF｜选择轮改为上传材料
Agent 已给出 1/2，用户没有选，而是直接上传旧简历或项目材料。
必须：重新判断材料成熟度，转入部分/完整材料分支，不逼用户补选 1/2。

### Case AG｜禁止混合首问
错误示例：`你之前有过工作经历吗？实习也算。如果手上有旧简历也可以给我。`
必须判为失败：这等价于未获用户选择就默认进入 Codex 路径。

### Case AH｜Phase 2 文件
完成后必须写或增量更新 `03_个人经历.md`，它是跨岗位事实母库，不是当前 JD 的改写版。

## Phase 3 · Resume

### Case AI｜证据矩阵先于简历
必须先生成 `04_证据矩阵.md`，0/1 证据不能包装成强项。

### Case AJ｜默认正式格式
有 DOCX 能力时必须按 `references/resume-format.md` 和 `assets/resume-template.docx` 生成 `05_简历.docx`；照片位保留，不泄露模板作者私人信息。

### Case AK｜一页溢出
优先删弱/重复内容与压缩表达，不应先无限缩字体。

## Phase 4 · Recruitment track

### Case AL｜简历完成准备找岗
Gate C 后才确认 1 校招/实习 / 2 社招 / 3 两者都看。

### Case AM｜Phase 4 读取企业树
必须从 `01_企业树.md` 搜索头部/中厂/小而美，不静默换成随机公司列表。

### Case AN｜校招/实习
优先官方 Campus/Graduate/Internship，Hard Gate 看届别、在校、开始时间、时长等，不混社招主池。

### Case AO｜社招
优先 Experienced/Professional，Hard Gate 看年限、必须经验、行业/管理经验、工作授权等，不混校招主池。

### Case AP｜两者都看
两套渠道分别搜索，结果可统一写 `jobs.csv` 但保留招聘体系字段。

## Phase 5 · Dashboard

### Case AQ｜自动打开看板
浏览器能力可用时：启动 Dashboard 后必须主动打开 localhost 并验证；不得只输出 URL。

### Case AR｜Dashboard 写回
必须确认稳定 `job_id` 写回并刷新后持久化；不能只看页面出现了岗位就算完成。

## 通用约束

一问一答；不编事实/数字/URL/岗位状态；岗位能力只决定追问方向，不决定答案；明确空白允许保留；Demo ≠ 上线；团队结果 ≠ 个人结果；AI 生成 ≠ 用户本人设计；发现信号 ≠ 质量结论；搜索完整但结果少可以通过，没搜完整却凑够数量不通过；第三方只做发现。
