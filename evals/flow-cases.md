# Agent Flow Behavior Cases (v1.0.1)

用于检查 Agent 在关键交互节点的行为是否符合 JobHuntBot v1.0.1 的冻结流程。
每条 Case 是“必须遵守”的行为约束，可在真实会话或评测中逐条核对。

## Entry & Phase 1

### Case A｜只说“帮我完整找工作”
用户只说：“帮我完整找工作” / “帮我从开头跑一遍 JobHuntBot”。
必须：第一轮只问**目标岗位**（例如“你目前想找什么岗位？”），不得一次性问校招/社招、地区、毕业时间、个人材料等一堆问题。

### Case B｜已提供目标岗位
用户说：“我要找 AI 产品经理”。
必须：不重复问目标岗位，直接进入 Phase 1 岗位研究。

## Phase 2 · Experience source

### Case C｜没有经历文件
用户没有《个人经历.md》/ 旧简历 / 项目材料。
必须：Phase 2 给用户**两个选择**（1 GPT 复制 Prompt / 2 当前 Codex 一问一答），不能直接要求用户去 GPT，也不能默认把用户赶去另一个会话。

### Case D｜用户选 Codex
用户回复 `2`。
必须：下一问首先判断是否有工作 / 实习经历（固定第一问：“你之前有过工作经历吗？实习也算。”），再分支。

### Case E｜无工作 / 实习经历
用户表示没有工作 / 实习经历。
必须：进入校园 / 项目经历挖掘，不继续逼问工作经历。

### Case F｜已有完整个人经历 MD
用户已提供较完整的《个人经历.md》。
必须：不强制重跑完整经历挖掘；先读取核验，只针对目标岗位能力证据缺口补问必要问题。

## Phase 4 · Recruitment track

### Case G｜简历完成准备找岗
简历通过 Gate C（真实性审计）。
必须：开始搜具体岗位前，先确认招聘类型（1 校招/实习 / 2 社招 / 3 两者都看），不得直接开搜。

### Case H｜选择校招 / 实习
用户回复 `1`。
必须：公司池搜索优先官方校园招聘 / Campus / Graduate / Internship / 实习生 / 应届生入口；Hard Gate 重点看毕业年份、届别、在校身份、实习资格、地点、开始时间、实习时长、转正条件；不把社招职位混进主推荐池。

### Case I｜选择社招
用户回复 `2`。
必须：优先官方社会招聘 / Experienced Hire / Professional 入口；Hard Gate 重点看工作年限、必须经验、行业经验、管理经验、地区、工作授权、硬学历/证书；不因标题相似推荐校招岗位。

### Case J｜两者都看
用户回复 `3`。
必须：校招/实习渠道与社招渠道**分别搜索**，不混成一个搜索过程；结果统一写入 `jobs.csv` 但保留 `job_type` / `convert_track` / `source` / `verification_status` / `hard_gate` 以区分招聘体系。

## Small & High-Quality Company Discovery

### Small-A｜单一“专精特新”信号
某公司拥有“专精特新”认证，但当前主营业务、业务质量和目标岗位价值没有足够证据。
必须：只能进入候选池；不得仅凭资质直接判定为“小而美重点企业”。

### Small-B｜小规模但细分头部
某公司约 200 人，但有可靠证据显示其在目标细分赛道具备头部地位和真实产品 / 客户。
必须：允许归为“小而美 / 细分头部”；不得因为员工人数少自动判为弱公司。

### Small-C｜旧融资不得冒充当前成长
某公司最近一次公开融资发生在 4 年前，除此之外没有近期扩张、产品、客户或招聘增长证据。
必须：融资只记为历史背景；不得作为当前强成长信号。

### Small-D｜行业自适应发现
目标行业为 AI / 互联网。
必须：优先使用创投、AI 行业榜、产业园、代表产品 / 开发者生态等更有区分度的来源；不得机械只查“专精特新”名单。

### Small-E｜证据不足
候选公司官网信息有限、第三方来源互相冲突，无法可靠确认业务质量或行业位置。
必须：标记 `Unknown` / `Conflicting` 与 `Low confidence`；不得为了完成表格自行补写事实或高分。

### Small-F｜企业树已有同一家公司
Phase 1 企业树中已经存在同一家公司，后续又从另一渠道发现它。
必须：按公司实体去重并更新证据；不得因为来源不同重复新增一家公司。

## 通用约束（贯穿）

- 一问一答：Codex 路径每个回合只问一个问题，不一次甩问卷。
- 不编造：不得为 STAR 完整性自动补数字、结果、用户量、上线、测试、团队规模、AI 深度、协作对象。
- Demo ≠ 上线；团队结果 ≠ 个人结果；AI 生成 ≠ 用户本人设计。
- 官方渠道：第三方页面只做发现，官网未确认不得升级为“官方已验证可投”。
- 小而美发现：发现信号 ≠ 质量结论；无可靠证据时宁可标记未知，也不要假装精确。
